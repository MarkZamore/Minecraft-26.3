# World Menu Policy

Встроенный клиентский компонент этой сборки, mod ID `lanmc_world_menu`, версия 1.0.0. Убирает из меню паузы кнопку «Настройки мира», через которую Minecraft 26.3 позволяет включить читы в уже созданном мире. Сохранённое разрешение читов не переписывается. Обычные настройки, «Открыть для сети» и «Жалобы» сохраняются.

## Механизм и границы

Компонент использует публичное клиентское событие NeoForge `ScreenEvent.Init.Post` с приоритетом `LOWEST`. На `PauseScreen` он удаляет только `Button`, чьи `TranslatableContents` имеют ключ `options.worldOptions.button`. Сравнение не зависит от языка. На каждом повторном построении меню, включая изменение размера окна, правило применяется снова.

`event.removeListener` вызывает штатный `Screen.removeWidget`, который убирает кнопку из отрисовки, клавиатурного/мышиного ввода и narration, а также снимает фокус. Список слушателей обходится по копии. Другие кнопки и исходные JAR не патчатся.

Защищена и ветка ошибки LAN. Существующий лаунчер создаёт `WorldOptionsScreen` для штатной публикации, но при неудачной публикации оставляет его видимым с переключателями читов и режима игры. Поэтому компонент не отменяет открытие или инициализацию: попытка LAN успевает выполниться. После инициализации он проверяет `Minecraft.getInstance().gui.screen()`: только если видимым всё ещё является тот же `WorldOptionsScreen`, вызывается его штатный `onClose()`. Успешная публикация, уже закрывшая экран, и переход на другой экран не затрагиваются.

Нативный `WorldOptionsScreen.onClose()` только возвращает предыдущий экран, не вызывая `applyChanges`; унаследованный `Screen.removed()` пуст. Это проверяется по настоящему байткоду вместе с порядком `Gui.setScreen`: ссылка на экран устанавливается до init, а после него не восстанавливается. Сохранённые читы, режим игры и сложность не переписываются.

Правило целиком принадлежит сборке: исходники, контракт, собственный JAR и публикационная проверка хранятся здесь. В лаунчере новых правил по имени сборки, инъекций или исключений не добавлено. Обычная доставка и Steam/идентичность остаются общей инфраструктурой лаунчера.

## Сохранение при обновлении Minecraft

Версии игры и NeoForge берутся из `portable-pack.json`. Условия вида `Minecraft == 26.3` нет. `build.py` компилирует исходники против официальных API объявленной платформы; нативные проверки используют те же артефакты. Metadata и `pack.mcmeta` формируются по фактической платформе.

Перед каждой публикацией CI обязательно:

1. Собирает компонент для текущего дескриптора и сравнивает результат с поставляемым JAR.
2. Проверяет настоящий native API, ключ и цепочку создания целевой кнопки, удаление через событие и сохранение остальных кнопок, безопасное закрытие видимого экрана после init, а также Minecraft serializer для `pack.mcmeta`.
3. Требует компонент и его встроенный контракт независимо от номера Minecraft. Удаление JAR вместе с его lock-записью тоже отклоняется.

При переходе, например, на 26.4 несовместимый API остановит публикацию до адаптации компонента. Это сохраняет обязательность правила, но не выдаёт ещё не выпущенную стабильную 26.4 за проверенную. После изменения платформы нужно заново собрать JAR, обновить его exact-hash lock и выполнить проверки; просто удалять компонент нельзя.

## Воспроизведение

Нужны Python 3.12+ и JDK 25. Сборщик скачивает только официальные клиентские/Maven-артефакты с проверкой контрольных сумм. Установщик, Minecraft client/server main и renderer не запускаются.

```powershell
$env:JAVA_HOME = 'C:\Tools\jdk-25.0.2'
python -B tools/world-policy/build.py --output .cache/world-policy/rebuilt.jar
python -B tools/world-policy/verify_native.py --jar mods/lanmc-world-menu-1.0.0.jar
python -B -m unittest discover -s tools -p test_world_menu_policy.py
```

Сверьте `.cache/world-policy/rebuilt.jar` с `mods/lanmc-world-menu-1.0.0.jar` побайтно. Публикационный workflow делает это автоматически. ZIP хранится без сжатия, с фиксированными временем и атрибутами; чужие библиотеки в JAR не включаются. Лицензия MIT вложена в `META-INF/LICENSE.txt`.

## Состав, происхождение и Safety

Исходный коммит `20badd173a215d2c1ba99978647f4e5090d9797f` проверен в независимой копии. Точные SHA256 всех 34 исходных файлов сохранены в `baseline-20badd1.json`. Существующие EMI, Iris, Sodium, конфиги логирования, JVM-аргументы и пресет не заменяются этим обновлением. Добавляется только клиентский JAR; он увеличивает количество загружаемых mod ID с трёх до четырёх. e4steam остаётся общим компонентом и не включён в поставку сборки.

У компонента нет самостоятельной страницы CurseForge/Modrinth: это собственный встроенный компонент, его официальные исходники, описание и загрузка находятся в репозитории этой сборки. Именно этот источник указан в `library/mod-pages.json`, а не одноимённый чужой проект.

Проверка необходимости Safety: код читает сообщение виджета, удаляет элемент клиентского меню и возвращает из видимого экрана настроек без применения изменений через штатный API. Он не вызывает изменения мира, chunk/palette, инвентаря, разрешений команд, caster/owner-механик и отложенных игровых действий; такие новые пути не добавляются. Обновлять Safety-профили и JAR других сборок для этого компонента не требуется. Авторские JAR не перепаковываются и helper-инъекции в них не добавляются.

Проверки выполняются без нового игрового прогона по последнему решению пользователя. Нативный JVM-префлайт проверяет API и поведение событий/виджетов, но не объявляется полным запуском клиента, мира или двух игроков. Предыдущий shader runtime-протокол описывает прежний состав и хранится отдельно.
